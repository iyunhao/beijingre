独立数据校验报告

数据说明

  • 五个视图：前两个为存量房口径——网上签约套数（全部存量房，含住宅、商业、办公等）与住宅签约套数（只含住宅），住建委月报同月同时公布这两个口径；第三、四个为期房 / 现房的网上签约套数与住宅签约套数（当日成交），各有「期房、现房、总计」三张月历；第五个为可售期房 / 未签约现房 · 其中住宅套数（库存存量），各有两张官方统计日历及一张相加日历。
  • 库存 tab 与成交 tab 不能混算：「可售期房统计 → 其中住宅套数」与「未签约现房统计 → 其中住宅套数」是某日市场上剩余的住宅库存（存量），而「期房 / 现房 · 网上签约」是当日成交（流量）。官方页只公示当前快照，按页面自报的截止日期逐日归档；本站每天自动采集、永久累积，并把 2020 年以来的网页存档稀疏锚点单独标注为「网页存档锚点」。日历空白 = 未采集（不是 0），不插值、不用日均凑数。
  • 更长的数据与「只增不删」：公开渠道可程序化获取的存量房连续逐日序列只有「最近一年」的滚动窗口；房市儿 /get_all 声称有 2015 年至今，但被微信「提取码」表单拦住、不提供数据接口，住建委历史逐日 ASP 接口也已下线。因此无法诚实回补更早的连续日历。本站已建立 history-archive.json 永久保护存档：每次重建先把全部历史日吸收进 append-only 文件，再把滚动窗口滑走的老日期原样带回、冻结数值，历史数据只增不删、时间轴会随时间自然变长。更长时间尺度则提供住建委「近五年房屋网上签约统计」的 2020–2024 官方年度汇总（见下方卡片），如实标注为年度值、不伪装成逐日数据；新 tab 的库存锚点也已回溯到 2020 年。
  • 数据来源：北京市住房和城乡建设委员会 · 存量房网上签约统计、房地产数据主题服务（官方公示页面）；存量房历史日序列、周合计、月合计取自北京房市儿（同口径转载），服务端每日抓取并累积入库。
  • 本月累计：有官方月报时以官方月报为准，否则为当月逐日加总。
  • 周末：有单日实值就单列，没有才显示合计：周六、周日只要都有确知单日值（住建委官方逐日统计表、每日官方直采，或由「周合计 − 工作日合计 − 另一侧实值」精确反推），日历就各占一格、各自显示当日实值并各自计算涨跌。只有两天单日值都不可确知时，才合并成一格显示「周六+周日合计」。合计仍是一等数据：官方逐日表覆盖期由两天实值相加，更早月份由周合计精确反推，源站整段缺失的周为估算值，鼠标悬停会标注来源与可信等级。半对周末（只披露了一天）按同一口径处理：已披露的一侧单列显示实值，另一侧显示「–」待披露，绝不拿合计或推算值冒充。
  • 默认口径与官方逐日表一致：默认视图为住宅签约套数，即住建委月报与官方逐日表所用的口径；「网上签约套数」为按当月住宅占比换算的口径，可一键切换。总量口径的月度折算差额只摊到工作日，不落到周末，避免月末恰逢周末时把「周六+周日合计」整体抬高或压低。
  • 内部拆分只在无单日值时使用：为了让月度合计、走势图与官方月报闭合，服务端对单日值不可确知的周末仍会在内部把合计拆到两天参与加总（仅在计算层使用）；该拆分是近似值，界面上一律隐藏，只显示两天合计。有官方逐日实值的周末直接展示真值，不存在内部拆分。新增周末日由每日采集直接写入官方直采存档，此后永远是实际值。
  • 期房 / 现房数据：取自住建委「房地产数据主题服务」页的当日两张表（网上签约套数 / 住宅套数）。该页只公示最新一天，历史逐日查询接口已下线且无存档，因此不存在可回补的连续历史曲线；本站从当前版本起每日自动采集、逐日累积，并把能找到的零散网页存档锚点单独标注。日期不连续，图中数值只代表当日实际签约量，不能相加当作期间累计。
  • 三张日历：期房 / 现房两个视图各有「期房、现房、总计（期房+现房）」三张月历，共用一个月份导航，并可用下拉框直接跳到有采集数据的月份。日历严格只显示已采集到的单日官方实际值，不插值、不按日均凑数：空白格 = 未采集（不是 0），右下角合计 = 本月已采集这几天的加总，不是整月网签量。「较上一采集日」只在同月存在两个及以上采集日时才计算，避免拿相隔数月的两个日子做无意义对比。
  • 100% 核对范围：npm run verify 会重新抓取住建委与北京房市儿原始页面，独立核对 8 项硬约束（工作日单日值、官方直采日、逐日住宅/总量月合计、官方月报锚点表、历史周末两天合计逐周反推、期房/现房当日值、数值合法性）。结果写入 server/data/verification.json，通过 /api/verification 与页面下方「独立数据校验报告」展示。能 100% 确证的数字都在报告里逐条列明；公开渠道根本不存在的数字（单日值不可确知的历史周末各自的单日值、源站整段缺口回补、期房/现房历史逐日值）一律标注为「不可确知」并如实披露，绝不冒充精确值。
  • 周合计校验：源站个别周的周合计是错的（如 2026-05-18 那周报 8,570，而同周工作日合计仅 3,801）。凡「周合计 − 工作日」超出全局中位数 3 倍的周，一律判定为不可信、改由官方月报锚定，不再把畸高残差当成周末值。
  • 缺口回补：2026-04-24 ~ 05-15 源站整段无数据（共 12 个工作日）。该区间用凤凰网房产「凰家周刊」公布的每周住宅网签套数作为各周强弱，在官方月报总量约束下按「星期效应 + 周末占比」回补，日历中标注为缺口回补，属估算值。
  • 涨 / 降：该日相对上一个有数据日的套数变化。
  • 缺口日期：源站确实缺失、又无法回补的日期显示「–」，不做插值、不按日均凑数。
  • 校准原则：月度差额只摊到推算值上，工作日原值一律不改动；有官方月报的月份，本站逐日合计与官方偏差均为 0.00%。
  • 每日刷新：服务端每 30 分钟抓一次，另在北京时间 09:05 / 22:05 强制刷新；数据超过 1 小时未更新时，任何接口请求都会触发后台补采（应对平台冷启动 / 进程回收）。网页每 10 分钟自动重拉一次数据。官方页约延迟 1~2 天发布，故最新日期通常滞后于当天。
  • 同比：去年同月的住宅网签量取自住建委月报（媒体/机构转载，见 server/data/external.json 逐条出处）。当月未结束只显示累计值，不做同比。
  • 链家签约：来自住建委「存量房网上签约月统计 · 按经纪机构」。市占率 = 链家签约套数 ÷ 全市网上签约总套数（同口径相除）。官方只保留最新一个月，历史月份由网页存档补齐，此后按月累积。
